# 隐秘潮痕：隐藏成就与跨媒介彩蛋

## 1. 文档状态

- 状态：设计确认，尚未进入实现。
- 玩家侧名称：隐秘潮痕。
- 内部语义：隐藏成就、彩蛋记录、发现加分。
- 适用范围：承接第一章和第二章已有生命史的轻量扩展，也可以让第三章及后续章节继续增加新的潮痕。
- 设计原则：彩蛋是潮池留下的异常记忆，不是额外的任务列表。

本系统不扩张第一章「生命诞生篇」的开局范围，也不改变第二章「生态爆发篇」已经完成的核心闭环。它只能在玩家已经经历过真实生态现象后，以额外发现的方式出现。

## 2. 体验目标

隐秘潮痕要让玩家产生三种感受：

1. 「我不是在清单里完成它，而是真的偶然发现了它。」
2. 「原来这个熟悉的梗被翻译成了潮池自己的生命现象。」
3. 「这个发现留下了记录，也让这份生命史更特别。」

它不能让玩家为了分数反复猜系统条件，也不能替代主线、生态循环、物种发现或生命史。

## 3. 完全隐藏的可见性规则

### 3.1 未解锁前

单个潮痕在解锁前必须完全不可见：

- 不显示成就名称、剪影、锁定图标、编号或完成数量。
- 不显示「还有多少个彩蛋」。
- 不在首页、底部导航、生态档案或排行榜评分拆分中展示隐藏入口。
- 不返回一个列出全部隐藏 ID 的玩家侧 API。
- 不因为玩家接近条件而显示进度条或明确提示。

玩家最多只能从潮池本身的异常水纹、事件重复、源质印记变化或生命史语气变化中获得非常轻的世界内暗示。暗示不能直接说出条件。

### 3.2 首次解锁

触发后按以下顺序反馈：

1. Phaser 潮池先表现异常现象。
2. 现有叙事队列接收一条新的发现记录。
3. 发现弹层展示潮痕名称、世界内描述和隐藏加分。
4. 玩家关闭或查看记录后，潮池记忆出现新的「隐秘潮痕」入口。

入口只在第一次发现之后出现。入口内只展示已经发现的记录，未来未解锁的记录继续保持不存在。

### 3.3 解锁后

已发现记录展示：

- 名称。
- 触发时发生的生态事实。
- 一句不公布精确公式的回响描述。
- 该记录贡献的隐藏加分。
- 可选的「远方回声」致敬说明。

不展示完整触发脚本、精确阈值或内部检测字段。玩家可以通过社区讨论和自己的实验推测条件，但游戏本身不把答案变成攻略表。

## 4. 触发设计规则

### 4.1 难，但必须可复现

- 每个潮痕优先组合 2 到 4 个已有条件。
- 条件可以跨越多个潮汐周期、事件或生命史记录。
- 触发必须由确定的状态和行为判断，不能只依赖不可验证的低概率随机。
- 如果包含随机生命出现，必须存在可重复的生态路线，而不是只能靠运气。
- 失败不能永久锁死记录；玩家应能在后续周期、后续生命史或另一份正常存档中再次尝试。

### 4.2 使用已有生命史

触发条件优先来自：

- 生产者、分解者、滤食者和其他生态角色的组合。
- 源质印记、演化选择、生态事件和水中回响。
- 物种的出现、繁盛、濒危、灭绝和遗产。
- 潮池在多个周期里的性格倾向。
- 玩家观察、等待、环境引导和特定输入行为。

玩家不能直接指定某个物种来完成彩蛋。即使彩蛋需要某个谱系，也应该由环境条件提高其出现和延续概率。

### 4.3 不破坏主线

- 隐秘潮痕不作为主线解锁条件。
- 不要求玩家放弃已经形成的正常生命史。
- 不要求新增常驻资源面板、完整参数表或后台日志。
- 不把彩蛋失败判定为生态失败。
- 彩蛋加分不能成为唯一高分路线。

## 5. 评分规则

当前生态评分继续由 packages/game-core 统一计算，优先表达纪元、演化、物种、遗产、源质印记和有限资源贡献。隐秘潮痕作为独立的发现加分加入评分，但权重必须受控。

建议规则：

- 隐秘潮痕分最多占非彩蛋生态评分的 15%。
- 使用确定的固定分值，不使用随机分数。
- 普通潮痕建议 1 分，稀有潮痕建议 2 分，传奇或双路线潮痕建议 3 分。
- 同一记录在同一存档中只计一次。
- 不因尚未发现任何彩蛋而扣分。
- 总分可以在解锁后立即增加，但未解锁前不显示「隐秘潮痕」这一评分分类。

排行榜和评分拆分在 UI 上必须遵守隐藏规则：没有发现任何潮痕时不出现该分类；发现第一条后，才可以显示「隐秘潮痕」及已获得的分数。

## 6. 反馈和视觉表达

彩蛋反馈要先让玩家看见潮池发生了什么，再让玩家读到记录：

- 水面短暂改变波纹、颜色、光照或生物聚集方式。
- 生态事件可以出现一次反常但不破坏平衡的结果。
- 潮池记忆中的记录使用比普通生命史更短、更有余韵的文案。
- 跨媒介彩蛋可以使用短暂的像素、霓虹、测试舱或故障感，但不能让首页长期变成另一款游戏的界面。
- 所有非必要动效遵守 reduced motion 设置。

发现弹层建议只包含：

- 潮痕名称。
- 一句世界内描述。
- 隐藏加分。
- 「收入潮池记忆」之类的自然命令。

不使用「系统成就」「触发条件」「完成率」等后台式表达。

## 8. 「无名小卒还是名扬天下」双路线

这组潮痕应该是两个独立记录，而不是一个显示两个锁定选项的公开成就。

### 无名小卒

- 让小型生态持续多个周期。
- 不让单一物种长期成为绝对优势。
- 主动干预次数较少，但不能靠等待造成灭绝。
- 让生产者、分解者和滤食者都留下稳定的生命史记录。

它表达的是：没有传奇物种，也没有巨大爆发，但潮池拥有完整、安静、可以延续的生活。

### 名扬天下

- 让一个罕见谱系通过环境引导自然出现。
- 让它连续经历多次生态压力并保持存活。
- 让它成为该存档中重复出现最强的源质印记或生命史回声。
- 不能通过直接指定物种或牺牲全部其他角色完成。

它表达的是：生命自己走到聚光处，玩家只是为它保留了能继续存在的环境。

同一轮生命史只结算其中一路。另一条路线必须在后续可延续的生命史路径中重新发现，不能通过重置存档清空历史来刷取。

## 9. 跨媒介联动边界

本系统采用「机制致敬、文案变体、视觉暗示」的方式，不默认构成官方联动：

- 不直接复刻其他作品的角色、Logo、原声、完整台词或界面。
- 不把外部作品名称变成主线资源、常驻按钮或世界观核心。
- 解锁后的「远方回声」可以让玩家看出致敬对象，但记录正文仍然使用潮池自己的语言。
- 网络梗优先使用常青梗，时效性很强的梗只作为可替换候选，不写入主线依赖。
- 每个彩蛋都必须先在生态逻辑上成立，再叠加玩家熟悉的联动回声。

## 10. 技术落点

实现时建议沿用现有 GameState JSON 快照和服务端权威规则：

- 在共享状态中增加可选的 hiddenTraces 结构，至少记录已解锁 ID、内部进度和已结算分数。
- 旧存档通过 normalizeGameState 补齐空的隐藏记录，不自动生成解锁结果。
- game-core 提供纯函数评估触发条件和结算隐藏加分，前端不能提交「我已解锁某彩蛋」作为事实。
- 环境操作、演化选择、生态事件结算、tick 和输入型交互都可以成为评估时机。
- 服务端只返回已解锁记录和当前可展示的发现反馈，不返回未解锁候选列表。
- 生命史可以复用现有记录机制；如果需要区分内部事件类型，再增加 hidden_trace 类型，不把它变成后台日志列表。
- 评分拆分增加 hiddenTraces 时，前端只有在首次发现后才渲染该分类。
- 任何阈值、顺序、概率保护和评分值都由代码与测试固定，不交给 AI 或文本生成器。

建议的核心测试覆盖：

- 正确触发每个首批潮痕。
- 相邻但不满足条件的状态不会误触发。
- 同一潮痕重复触发不会重复计分。
- 旧存档归一化后不会凭空解锁。
- 隐藏分值始终在上限内，且不能压过生态主体评分。
- 未发现任何潮痕时，UI、排行榜拆分和 API 展示都不泄露候选列表。
- 移动端等价手势和 reduced motion 状态都能完成可访问的反馈。

## 11. 验收标准

这套机制完成后，玩家应该能够：

- 在没有看到成就清单的情况下偶然触发一条彩蛋。
- 先从潮池画面感知异常，再在潮池记忆中读到记录。
- 通过记录和后续实验逐渐猜出某些彩蛋的来源，但不会看到精确攻略。
- 发现彩蛋后获得少量评分提升，但不需要彩蛋也能完成主线和形成生态循环。
- 在不同生命史中体验「安静延续」与「留下名字」等不同结果。

开发验收不能只检查字段和分数，还要检查未解锁状态是否真的没有入口、占位和计数。
