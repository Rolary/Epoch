# 《生态纪元》移动端玩法与 UI 约束

移动端体验应像一款可玩的放置手游，而不是资源控制面板。第一阶段的界面必须服务于一个目标：让玩家养出第一只生命。

## 1. 信息层级

首页优先级：

1. 活着的潮池场景。
2. 当前主线状态。
3. 可拖拽的发光养料。
4. 少量关键资源或状态。
5. 已解锁入口。

不在首页长期展示：

- 全量资源表。
- 全量环境参数。
- 大段专业解释。
- 多个并列系统卡片。
- 后台式日志列表。

## 2. 主操作

第一阶段主操作是：

```text
把潮池周围的发光养料拖进水里。
```

交互要求：

- 发光养料要有入场和出场效果，不能突然出现或消失。
- 不同颜色养料可以影响不同状态，但开局只强调“先让它活起来”。
- 紫色和金色印记可以更稀有、更醒目，但不能让玩家误以为必须等稀有物才能推进。
- 拖入后要有水面、粒子或短反馈，表示潮池发生变化。

## 3. 主线任务框

任务框不能长期挤占主画面。

行为：

- 首次进入自动展开。
- 展示几秒后通过缩放动画收回状态栏。
- 收起状态保留关键信息，例如阶段名和进度。
- 首次自动收起后要记住状态，玩家切回潮池时不反复展开。
- 玩家点击可展开，再点可收起。

文案原则：

- 大字说玩家目标。
- 小字只做自然补充。
- 不使用 `专业概念：`、`系统名：` 等设计者前缀。
- 文明、意识和群星只能作为短远景出现，不能挤占主线目标或拖拽操作。
- 主线展开态可显示低饱和远景条，但必须保持紧凑，不能遮住潮池主场景。

## 4. 底部入口

底部入口渐进出现：

```text
首页 -> 演化 -> 图鉴 -> 遗产 -> 生命史 -> 档案
```

命名要求：

- `日志` 改为 `生命史`。
- `设置` 改为 `档案` 或页面内 `生态档案`。
- 入口不是后台功能名，而是玩家理解的世界内入口。

## 5. 演化页

节点状态：

- 已解锁：明亮、稳定、可信。
- 可解锁：高亮、脉冲或闪烁，下方提醒点同步强调。
- 未解锁：低饱和但可读，不要暗到像不可用错误。

按钮文案：

- 不用 `确认这一步`。
- 根据节点语义使用 `点亮这道痕迹`、`让它延续`、`记录这个跃迁` 等自然说法。

## 6. 生命史

生命史不是系统日志。

- 入口：`生命史`。
- 页面标题：`潮池记忆`。
- 空状态：`潮池记忆尚未开始。若生命能留下第一道痕迹，这颗星球的故事就会有第一行。`
- 重复操作合并为自然描述，例如：
  - `潮池连续吸收了几次能量闪光，水面变得更活跃。`
  - `矿物颗粒多次沉入池底，新的附着面正在增加。`
  - `潮水反复带回养料，生命材料正在富集。`
- 物种发现、纪元推进、遗产沉淀、印记获得保持独立关键记忆。

## 7. 生态档案

生态档案替代传统设置页。

分组：

- 潮池身份：生态名称、当前纪元、生态倾向。
- 成长记录：演化节点、物种、遗产、源质印记。
- 当前状态：主要资源、稳定性、突变倾向、生命成形进度。
- 存档信息：游客印记、存档 ID、最近更新时间。

重置本地存档必须放到底部危险操作区，文案明确且需要二次确认。

## 8. 移动端验收

- 单手可完成首次拖拽。
- 主线收起后，潮池仍是视觉中心。
- 文字不溢出按钮、卡片或状态栏。
- 专业词不抢占玩家目标。
- 首页、演化、图鉴、遗产、生命史、生态档案都不像后台管理系统。
