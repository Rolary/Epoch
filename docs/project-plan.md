# 《生态纪元》项目方案

## 1. 产品定位

《生态纪元》是一款网页端放置演化游戏。玩家从一片始源潮池开始，通过环境引导、演化节点、随机事件和生命记录，见证一颗星球自己的生命史。

长期表达：

```text
从潮池到群星，见证一颗星球自己的生命史。
```

第一阶段表达：

```text
把一池还没有生命的水，养出第一只生命。
```

当前完成基线：

```text
第二章：生态爆发篇（功能完成，进入稳定维护）。
```

第一阶段与第二章均已完成基础闭环，后续作为稳定基线维护。下一章正式立项前，只处理缺陷、平衡、性能和兼容问题，不继续扩大第二章范围。

## 3. 第一阶段范围

第一阶段只做「生命诞生篇」，目标是完成一个清晰可玩的早期闭环。该阶段已经完成基础开发，后续只作为稳定基线维护，不再继续扩大范围。

必须包含：

- 创建生态：生态名称 + 源质印记。
- 潮池首页：拖拽发光养料，让潮池出现生命材料。
- 主线任务：围绕「养出第一只生命」，每次浏览器打开或刷新后首次进入潮池时自动展示，随后收起到状态栏。
- 演化路径：已解锁、可解锁、未解锁状态清晰。
- 第一种生命：发现弹层、图鉴记录、生态影响。
- 生命史：合并重复事件，展示潮池记忆。
- 生态档案：身份、成长、状态、存档信息。
- PostgreSQL 存档：服务端权威存档，刷新和 App Platform 更新部署后可恢复。

不放入第一阶段：

- Prisma。
- 真实 AI 服务。
- 正式账号、多设备同步、分享。
- 完整多纪元流程。
- 文明和星际生态阶段。

## 4. 核心循环

```text
拖入发光养料
-> 潮池状态变化
-> 主线进度推进
-> 解锁演化节点
-> 遇到潮池事件并做出取舍
-> 留下互斥演化倾向
-> 形成生命痕迹
-> 出现第一种生命
-> 写入图鉴与生命史
-> 物种组合、灭绝遗产和源质印记影响后续生态
```

循环重点不是刷资源，而是让玩家理解：

```text
我的操作正在把潮池推向生命出现。
```

## 5. 玩家侧命名

当前玩家侧命名必须统一：

- `生命史`：底部入口。
- `潮池记忆`：生命史页面标题。
- `生态档案`：设置页重构后的页面标题。
- `图鉴`：物种记录入口。
- `遗产`：化石、祖先和历史沉淀入口。

避免使用：

- `日志` 作为玩家侧入口。
- `设置与存档` 作为主页面表达。
- `专业概念：`、`系统名：` 等前缀。
- 后台表格、系统记录、纯列表堆叠。

## 6. 技术路线

当前实现路线：

- React + Phaser + Vite 前端。
- Fastify + TypeScript 后端。
- `packages/game-core` 作为前后端共用规则。
- Zustand 桥接 React 与 Phaser。
- PostgreSQL 存档；本地开发默认连接 `localhost:5432/epoch`，生产通过 `DATABASE_URL` 连接。
- 本地生成器负责物种和生命史表达。

后续可升级：

- Prisma：当需要复杂关系查询、多用户、分享或后台统计时再评估。
- 真实 AI：当图鉴、物种插画和生命史报告需要更强个性化时再接入。

## 7. 长期章节路线

长期主线采用 8 章结构。章节名后续可以微调，但顺序与节奏先按以下路线执行：

1. **生命诞生篇**：把一池还没有生命的水，养出第一只生命。
2. **生态爆发篇**：让第一种生命不只是出现，而是在潮池里形成真正的小生态。
3. **海陆分化篇**：让生命离开单一潮池，开始占据不同环境。
4. **复杂生命篇**：让生命从简单群落走向身体、感知、捕食、防御和复杂生态网络。
5. **意识萌芽篇**：让生命开始记忆、学习、迁徙、协作，并第一次“理解”世界。
6. **文明初火篇**：语言、仪式、农业、城市和早期技术出现，但玩家仍不直接扮演统治者。
7. **星球危机篇**：文明与生态共同面对气候、资源、污染、灭绝和星球级后果。
8. **群星生态篇**：经历母星危机后的生命史进入轨道、卫星、异星和群星生态。

每一章都必须有一句玩家可复述的主线目标，并继续遵守“玩家是观察者和引导者，而不是全知创造者”的身份约束。

## 8. 第二章完成基线：「生态爆发篇」

第二章「生态爆发篇」已经完成核心闭环，承接第一章结尾，并作为后续章节不得破坏的稳定基线。

第二章主线：

```text
让第一种生命不只是出现，而是在潮池里形成真正的小生态。
```

玩家侧目标：

```text
这片潮池已经有了第一种生命。现在让它们分化、互相影响，并形成可以延续的生态循环。
```

阶段条：

```text
追逐光照 -> 分化角色 -> 形成循环 -> 面对失衡 -> 留下生态性格
```

核心阶段：

- **光合作用前夜**：从第一章末尾的 `感光色素` 承接，出现“生命开始追逐光”的主线反馈。
- **第一批生态角色**：至少形成生产者、分解者、滤食者三类早期角色。
- **生态组合显现**：不同角色组合产生世界内反馈，例如“分解层正在喂养新的生产薄膜”。
- **生态事件升级**：事件从“潮池现象取舍”升级为“生态平衡取舍”，例如爆发繁殖、浑浊缺氧、分解层扩张、滤食孔隙失衡。
- **生态性格归纳**：生命史开始总结潮池倾向，例如稳定循环、突变爆发、共生网络、极端适应。
- **第二章收束**：玩家看到第一个小生态循环形成，而不是只有单个物种存活。

当前第二章实现原则：

- 阶段推进以“软见证”为主，避免把章节改成强任务链。玩家可以快速推进节点，但主目标、反馈和生命史要清楚记录已经见证过的生态时刻。
- 生态共鸣在玩家表层优先称为“水中回响”。水中回响、生态事件和主线分岔属于会留下痕迹的判断，执行前需要确认框说明会留下什么、会让哪里承压。
- 第二章完成后冻结玩法范围，只接受缺陷修复、平衡调整、性能优化和旧存档兼容修复。

第二章结尾验收句：

```text
这片潮池已经不只是有生命，而是有了自己的生态循环。
```

第二章暂不引入：

- 正式文明系统。
- 多地图大世界。
- 真实 AI 服务。
- 账号、分享、多设备同步。
- 复杂后台统计或 Prisma。

## 9. 第一阶段收口记录

已完成并作为基线保留：

- PostgreSQL 替代本地文件存档，避免 App Platform 容器更新丢失数据。
- 文档全部从 JSON / SQLite 一阶段路线修正为 PostgreSQL 一阶段路线。
- 首页主线任务收起行为稳定，不遮挡潮池；每次浏览器打开或刷新后会重新展示一次，同一页面会话内切回潮池时不反复自动展开。
- 演化页可解锁提醒足够明显。
- 生命史不再像系统日志。
- 生态档案不再像设置表单。
- 文档中的 `日志`、`设置与存档`、`localStorage 自动存档`、`静态网页原型` 等旧路线清理干净。

后续维护时继续检查：

- 移动端文字不溢出。
- 发光养料入场和出场自然。
- 图标资产命名和引用稳定。
- 当前实现记录更新到文档，避免后来者按旧描述开发。

- 存储方案、API、数据结构。

- 首页交互和演化页状态表现。
- 图鉴、生命史、生态档案的信息架构。

```text

设置与存档
```

## 11. 成功标准

第一阶段成功不是内容多，而是新玩家能复述：

```text
我要把这片潮池养出第一只生命。
```

并能理解自己刚刚完成了什么：

```text
我把发光养料拖进水里，潮池出现生命材料；随后出现痕迹、复制和第一种生命。
```

如果玩家只感受到资源数值上涨，而没有感到生命史发生变化，就不能把改动合入第一章基线。

## 12. Roguelike 定义

当前项目的 roguelike 不是死亡重开，也不是清空生命史。它指：

- 潮池事件提供三选一取舍，结果写入生命史。
- 演化节点存在互斥分支，让每份存档留下不同延续倾向；同层互斥分支应使用相同解锁条件，避免资源门槛替玩家做选择。
- 物种兴衰会形成组合效果和遗产代价。
- 源质印记影响事件池、物种倾向和长期路线。
- 这些机制采用“现象先行”引导：先看到潮池变化，再通过生命史和生态档案逐步理解。

## 13. 后续系统候选：潮汐回响

`docs/tidal-echo-gacha.md` 记录了潮汐回响设计草案。该方向把抽卡包装为纯游戏内的生态投料实验：消耗多种资源，支持单次/十连回响，奖池包含普通资源结果和蓝/紫/金源质印记，并通过回响残痕与保底保护节奏。

该系统属于第二章之后的轻量成长扩展，不接真实付费，不作为主线进化、物种发现或生态循环的必经条件。
## 后续系统候选：匿名公开排行榜

排行榜路线按“先轻量、后分层”推进：

- v1 实现全服匿名总榜，只展示生态名、生态评分和成长摘要，不展示 `guestKey`、`saveId` 或任何可恢复身份的信息。
- 生态评分由 `packages/game-core` 统一计算，优先表达演化节点、纪元推进、物种记录、遗产沉淀和源质印记，资源只作为有上限的辅助项，避免纯挂机堆资源成为唯一目标。
- 后续可扩展赛季榜、好友榜、地区/分区榜；这些方向需要正式账号、社交关系或分区字段后再设计，不进入 v1 实现。
