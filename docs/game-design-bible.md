# 《生态纪元》游戏设计总纲

本文档是后续产品与开发调整的最高层设计约束。任何新系统、页面、数值或 AI 生成能力，都必须服务于这里定义的体验方向。

## 1. 核心概念

```text
从潮池到群星，见证一颗星球自己的生命史。
```

游戏覆盖从生命起源到文明与星际生态的长期演化过程。第一阶段「生命诞生篇」与第二章「生态爆发篇」已经完成基础闭环，当前作为连续生命史的稳定基线维护。所有后续设计都要承接这两章留下的潮池记忆。

长期主线采用 8 章结构：

```text
生命诞生 -> 生态爆发 -> 海陆分化 -> 复杂生命 -> 意识萌芽 -> 文明初火 -> 星球危机 -> 群星生态
```

每一章都必须承接前一章留下的生命史，不允许突然跳到脱离生态记忆的新系统。

## 2. 第一阶段基线

第一阶段已经完成基础开发，后续作为开局基线维护。面向玩家的第一目标必须始终足够简单：

```text
把一池还没有生命的水，养出第一只生命。
```

玩家不需要先理解专业概念。专业内容可以藏在详情、节点副标题或生态档案里，但不能成为开局理解入口。

文明、意识和群星生态只能在开局作为远景伏笔，在主线大节点作为短回响出现。它们不能提前变成玩家任务、资源压力、系统入口或强制剧情说明。玩家第一眼仍然只需要理解：

```text
先把这片潮池养出第一只生命。
```

## 2.1 第二章完成基线

第二章为「生态爆发篇」，已经完成核心闭环。它不能反向挤压第一阶段，而是在第一种生命出现后继续推进：

```text
让第一种生命分化出不同生态角色，并形成可以持续的小循环。
```

第二章的玩家侧目标是：

```text
这片潮池已经有了第一种生命。现在让它们分化、互相影响，并形成可以延续的生态循环。
```

第二章阶段条为：

```text
利用光照 -> 分化角色 -> 形成循环 -> 面对失衡 -> 形成生态倾向
```

第二章的重点不是新增更多资源面板，而是让玩家看见生产者、分解者、滤食者等早期角色开始互相影响，生态事件从潮池现象取舍升级为生态平衡取舍，生命史开始总结潮池性格。

## 2.2 第三章设计启动边界

第三章暂定为「海陆分化篇」，设计从第二章完成时的第一阵往复开始：潮水退去，潮池边缘露出湿岩和湿润岸缘，已有生命第一次面对不同栖位。玩家侧目标是：

```text
让第一阵往复越过水线，在相连的栖位上留下可以延续的生命。
```

第三章只扩展同一片潮池的水线，不做多地图大世界。浅水、潮间湿岩和湿润岸缘是同一场景中的相连栖位；章节完成默认要求至少两个栖位建立跨水线往返。栖位是生态事实，不是新资源，物种仍由角色、历史、源质印记和事件共同形成，玩家不能直接指定哪个物种上岸。

第三章新增节点、事件和生命史字段必须复用第二章的演化、生态事件、生态互动、图鉴、遗产和叙事队列。不能用独立货币、完整参数表或常驻地图面板把首页变成管理工具。

第三章还必须有独立的体验辨识度：水线要在同一场景中进退，生命要在岸边留下可回看的痕迹，事件选择要先改变眼前的水势再写入生命史，章节总结要能以视觉记忆回看水线如何形成。若画面只是第二章场景加上新标题，或选择关闭后没有世界反馈，则不视为完成第三章设计。

## 3. 玩家身份

玩家不是全知创造者，也不是文明领袖。玩家更像一名观察者和引导者：

- 不能直接指定创造某个物种。
- 可以调节环境、投入养料、施加选择压力。
- 可以提高某类生命出现的概率，但不能完全决定结果。
- 需要接受繁盛、分化、失衡、灭绝和遗产共同组成生命史。

## 4. 不可违背规则

- 不做轮回重置。
- 不清空玩家已有生命史。
- Roguelike 方向只表现为不可逆生命史分支、随机事件、演化取舍、物种组合和遗产代价，不表现为死亡后清空重来。
- 不把灭绝做成单纯失败。
- 不让 AI 决定核心数值、价格、概率或解锁条件。
- 不把首页做成资源控制面板。
- 不在开局展示完整资源表、完整环境参数、完整演化树和完整导航。
- 不让玩家第一步遇到资源不足。
- 不把图鉴做成纯文本收藏，物种必须尽量有生态功能。
- 不用单一资源门槛推进关键阶段。
- 不新增脱离「生命史推进」的孤立系统。

## 5. 首页判断标准

首页必须帮助玩家回答：

```text
我现在怎样让这片潮池离第一只生命更近？
```

首页必须包含：

- 一个当前主线目标。
- 一个活着的潮池主场景。
- 一个清晰主操作：拖拽发光养料进入水里。
- 少量关键状态。
- 最近一次主题反馈。
- 只展示已解锁入口。

首页禁止：

- 全量资源列表。
- 全量环境参数。
- 多个并列系统面板。
- 后台仪表盘式布局。
- 长时间占据主画面的巨大任务框。

## 6. 渐进解锁

系统必须随着主线逐步出现：

```text
创建生态：生态名称、源质印记
富集材料：潮池、主线、拖拽养料
接近首次节点：解锁演化入口
出现第一种生命：解锁图鉴
出现筛选或遗产：解锁遗产
经历多次关键变化：解锁生命史
```

每次新入口出现，都要通过主线反馈、事件弹层或奖励弹层承接，不能静默增加按钮。

新入口引导必须遵守：

- 文案只说世界内发生了什么、玩家为什么要关心，避免使用“屏幕右下角”“底部按钮”“页面入口”等界面位置描述。
- 演化入口只在第一个演化节点已经可点亮时给出提示，不能在资源还未达到时提前催促。
- 同一轮状态变化解锁多个入口时，必须进入串行导览队列：一次只展示一个奖励弹层，等玩家亲自打开当前新入口后，再展示下一个。
- 弹层出现和消失都要有短动画承接，不能直入直出；强动效只用于解锁、奖励、危险和首次引导。
- 游戏内操作默认需要有可感知反馈，例如养料入水、水面反应、节点点亮、入口浮现、弹层收束；除非是纯文本设置，不要让状态突然切换。
- 所有非必要动效必须尊重 reduced motion 设置。

长期生命史可以在主线详情里作为低饱和远景展示：

```text
生命诞生 -> 生态爆发 -> 海陆分化 -> 复杂生命 -> 意识萌芽 -> 文明初火 -> 星球危机 -> 群星生态
```

当前阶段只高亮正在发生的章节，后续章节作为未来痕迹存在，不要求玩家现在理解或操作。

## 6.1 生命史分支

Roguelike 玩法必须用“现象先行”的方式让玩家自己发现：

- 第一次只显示潮池现象和三种世界内选择，不展示完整概率表。
- 第二次或多次出现相似倾向时，生命史开始归纳潮池性格。
- 生态档案只在倾向累计后显示简短解释。
- 演化分支允许互斥取舍，例如提高复制稳定、保留复制错误或增加旁支分化；同一层级的互斥分支应使用相同解锁条件，让玩家感到是在多选一，而不是被不同资源门槛推向某个答案。
- 物种组合和灭绝遗产需要影响后续生态，让坏事也成为生命史的一部分。

## 6.2 隐秘潮痕

隐藏成就和彩蛋统一称为隐秘潮痕，完整规则见 docs/hidden-achievements-and-easter-eggs.md。

它们必须承接已有的物种、源质印记、演化选择、生态事件、遗产和生命史。未解锁的潮痕不显示名称、图标、数量、锁定占位或评分分类；首次发现后，才通过潮池反馈和潮池记忆出现入口，并且只展示已发现的记录。

隐秘潮痕只提供有上限的少量评分加成，不作为主线条件，不把首页改造成成就列表，也不能让玩家直接指定物种来完成彩蛋。跨游戏、网络和影视梗只能作为机制致敬或叙事回声，不能脱离潮池生态逻辑单独存在。

## 7. 玩家侧命名

玩家看到的是世界内表达，不是设计者或系统后台表达：

- `日志` 统一改为 `生命史`。
- 生命史页面标题为 `潮池记忆`。
- `设置` 统一改为 `生态档案`。
- 不使用 `专业概念：`、`系统名：` 这类前缀。
- 专业词可以出现，但要自然融入副标题、详情或档案描述。

## 7.1 游戏文案准则

玩家首先要读懂眼前发生的生态现象，其次才是世界观含义。所有主线目标、解锁弹层、事件和生命史记录遵循：

- 标题说明发生了什么，例如“池底材料回到了浅层”，不使用“新的痕迹正在发亮”一类泛化标题。
- 正文描述可以观察到的水色、结构、位置、材料流动或生存压力。
- 操作提示直接说明下一步动作，不用诗意句代替交互信息。
- 数值、概率、持续时间和互斥规则单独说明，不混入叙事句中。
- `痕迹`、`回响`、`沉淀`、`潮池记住自己`不能作为所有功能的通用代称；只有对应具体世界概念时才使用。
- 避免高频使用“不只是……而是……”“真正……”“把偶然变成未来”等抽象升华句式。
- 潮池可以通过水势和生命反应表现状态，但不写成会思考、愿意或替玩家作决定的角色。
- 同一弹层的描述、影响和建议必须提供不同信息，不能连续三次改写同一结论。

## 8. AI 使用边界

AI 或本地生成器负责让生命史更独特：

- 物种命名。
- 物种描述。
- 外观提示词。
- 习性标签。
- 谱系摘要。
- 生命史文本。
- 事件叙事包装。

AI 不负责：

- 资源公式。
- 节点价格。
- 事件概率。
- 惩罚强度。
- 主线解锁条件。
- 关键数值平衡。

系统必须先生成结构化生态事实，再让 AI 或本地生成器生成表达。

## 9. 第一阶段成功标准

第一阶段已经完成基础闭环。它的成功标准继续作为回归基线：玩家能在 10 到 20 分钟内明确感受到：

```text
我从一片潮池开始，推动材料富集，见证结构稳定、复制出现、细胞诞生，并记录下属于这颗星球的第一段生命史。
```

如果玩家只觉得自己在点资源按钮、看面板涨数值，则设计失败。
