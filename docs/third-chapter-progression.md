# 《生态纪元》第三章主线推进：海陆分化篇

> 状态：体验切片实现版。共享状态、首批节点、引潮动作、退潮晒痕、首次岸线往返、第三章主目标与三段潮池记忆已经接入；首批湿岩、三种岸痕、事件主图和跨水线姿态资产已替换代码占位，完整章节仍按开发规划扩展。

## 1. 章节定位

第二章结束时，生产、分解和过滤已经接成第一阵往复，潮池也留下了自己的生态性格。第三章不重新养一套生命，而是让这阵往复第一次遇到“空间”：潮水退去，边缘露出湿岩和湿润沉积物，已有生命开始面对不同的水分、光照、温度和附着条件。

第三章的“陆”只从潮池边缘开始。它不是切换到多地图大世界，也不是立刻进入陆地文明，而是让同一片潮池形成一条可以被看见的水线梯度：浅水仍在，潮间湿岩出现，湿润岸缘逐渐成为新的落脚处。

玩家继续是观察者和引导者。玩家可以改变潮水、光照、矿物流动和选择压力，帮助某些栖位更容易稳定，但不能直接指定哪一个物种上岸，也不能保证某个谱系一定成功。

## 2. 玩家目标

章节主线：

```text
让第一阵往复越过水线，在相连的栖位上留下可以延续的生命。
```

玩家侧目标：

```text
这片潮池已经有了自己的循环。现在让生命越过水线，在湿岸和浅水之间找到新的落脚处。
```

玩家完成后应能复述：

```text
生命已经越过水线，潮池开始拥有自己的岸线。
```

第三章的完成不是“拥有更多物种”，而是同时满足三种可见变化：

- 至少一个已有生态角色在非浅水栖位留下稳定谱系。
- 至少两个相连栖位被生命史记录，并且仍然能互相交换材料或影响。
- 玩家亲自面对过一次干湿、盐分或冲刷造成的岸线压力，并留下一个不可逆倾向。

玩家不需要看到这些条件的数字。主线、场景和潮池记忆要先让玩家看见现象，再逐步归纳出“这片水怎样走向岸边”。

## 3. 阶段条

```text
发现水线 -> 附着湿岸 -> 分出栖位 -> 承受干湿 -> 恢复往返 -> 形成岸线记录
```

| 阶段 | 玩家理解 | 世界反馈 | 见证记录 |
| --- | --- | --- | --- |
| 发现水线 | 潮池之外也有可以留下生命的地方 | 退潮露出一圈湿岩和湿润沉积物，主场景出现水线 | `waterline_exposed` |
| 附着湿岸 | 已有生命在湿岩上稳定停留 | 生产者、分解者或滤食者的某一支随水流抵达边缘 | `shore_colonized` |
| 分出栖位 | 同一阵生命在不同水分里工作 | 浅水、潮间湿岩、湿润岸缘中至少两处出现稳定痕迹 | `niche_split` |
| 承受干湿 | 岸边的繁盛会被晒干、冲散或盐化 | 岸线事件出现，三种世界内选择留下不同压力和倾向 | `dry_wet_pressure` |
| 恢复往返 | 湿岸生命仍然依赖浅水循环 | 岸边碎屑回到水中，或潮水把浅层材料带向岸边，形成跨栖位往返 | `shoreline_exchange` |
| 留下海陆痕迹 | 潮池开始拥有一条自己的边界历史 | 生命史归纳第一次岸线性格，第三章完成 | `shoreline_memory` |

第三章采用第二章的软见证方式。玩家可以先点亮节点，也可以先从场景和事件里看见倾向；只要关键现象被真正看见，章节进度就能向前，不把它变成必须逐项打勾的后台任务。

## 4. 核心体验

### 4.1 一片潮池，三种相连栖位

第三章默认使用三种栖位作为理解框架：

- `浅水`：第二章循环的原有中心，水分和养料最稳定。
- `潮间湿岩`：周期性被潮水覆盖，适合附着、筛选和反复暴露。
- `湿润岸缘`：更接近陆地，水分不稳定，但光照、矿物和新的附着面更多。

这三处必须在同一个潮池场景中逐步露出，不单独变成三张地图。章节完成默认要求“浅水 + 任一岸线栖位”形成往返；第三处栖位是可继续展开的分支，不作为第三章的硬性全收集条件。

### 4.2 栖位是生态事实，不是新资源

第三章需要让物种同时拥有“做什么”和“住在哪里”两层信息：

- 生态角色继续沿用生产者、分解者、滤食者、共生者、耐受者等既有分类。
- 栖位记录补充它主要在浅水、潮间湿岩还是湿润岸缘活动。
- 同一角色可以因源质印记、历史倾向和事件选择而进入不同栖位，不能用角色名称直接决定结果。

第一版不新增“岸线点”“湿度币”或人口资源。岸线变化由现有资源、环境、历史标签、物种状态和事件结果共同推导；只有玩家真正看见的栖位和关系才进入潮池记忆。

### 4.3 岸线回响是水中回响的延伸

“岸线回响”不是独立的抽取池、技能栏或新货币，而是第二章“水中回响”在空间扩展后的表现：

- 岸边的碎屑是否能回到浅水。
- 浅水的养料是否能被带到湿岩。
- 某一次暴露是让谱系更稳，还是让旁支更大胆。

它可以复用现有生态干预页的确认框和回响卡片。玩家看到的是“这阵水势会把哪里接起来”，而不是倍率表。

### 4.4 第三章的体验支柱

第三章不能只表现为演化页多出几个节点。即使玩家不阅读专业解释，也应该从画面、节奏和反馈中感到“生命第一次拥有了边界”。体验辨识度锁定为以下五点：

1. **水线会呼吸**：潮水在同一片场景里缓慢进退。水线退去时，湿岩变暗、附着面反光、湿润沉积物露出；回潮时，水纹把岸边碎屑带回浅水。玩家看到的是空间正在变化，而不是地图加载。
2. **同一支生命会有两种姿态**：生产薄膜在水下更明亮，在暴露边缘更贴附；分解者在池底成片，在湿岩裂隙中变成零散痕迹；滤食者在回潮时活跃，在退潮时收拢。这里表现的是同一生态角色对栖位的反应，不是玩家直接选择一个新物种。
3. **生命会留下岸痕**：一次选择不能只弹出文字和数值。水线附近要留下短时间可见的薄水膜、盐晶、冲刷沟或附着斑，之后即使玩家离开弹层，也能从场景看出这片潮池经历过什么。
4. **选择先改变眼前的世界**：岸线事件的三个选项在确认前给出轻量的场景预示，例如边缘保持湿润、湿岩出现结面或回潮水纹变强；确认后先播放水线反馈，再写入资源、历史和物种状态。玩家先感到取舍，再逐步理解后果。
5. **潮池记忆可以回看**：第三章收束时，生命史不是新增一页记录，而是把“水线露出、第一次贴岸、一次失衡、第一次回流”组成一条短的视觉记忆带。玩家可以看到这片水从完整潮池变成拥有边界的生态。

第三章的体验验收有三条反向标准：如果截图只看得到第二章场景加上“海陆分化”标题，设计失败；如果岸线事件关闭后场景没有留下变化，反馈不完整；如果潮池记忆仍然只是文字列表，章节还没有形成自己的表达。

## 5. 玩家引导和不可逆分支

### 5.1 环境引导

现有环境干预继续作为主要引导方式，第三章只改变它们在场景中的意义：

| 世界内倾向 | 玩家感受 | 可能留下的压力 |
| --- | --- | --- |
| 延缓水膜蒸发 | 岸边薄水膜维持更久，稳定谱系存活率提高 | 扩散变慢，矿物和光照优势暂时没有完全释放 |
| 完全暴露湿岩 | 允许更大胆的附着和突变 | 干燥、盐晶或冲刷更容易让脆弱谱系退出当前生态 |
| 随潮往返 | 让水线两侧交换更频繁 | 任一处失衡都可能更快传回另一处 |

这些是提高倾向的引导，不是物种召唤按钮。服务端和 `packages/game-core` 仍决定事件概率、数值变化、谱系生成和灭绝结果。

### 5.2 海陆分化的互斥倾向

“栖位分化”之后出现一个与第二章同层级的互斥分支组。三条分支使用相同解锁条件，让玩家感到自己是在选择潮池的走向，而不是被资源门槛替选：

- `延缓水膜蒸发`：潮间边界维持更久，生命延续更稳定，但岸线扩张较慢。
- `攀住湿岩`：更容易利用矿物和附着面，分化更大胆，但干湿压力更高。
- `随潮播散`：更容易把生命带到相邻栖位，交换更活跃，但局部稳定性更难维持。

分支只留下倾向，不把后续物种锁死。旧谱系、源质印记、生态角色和后续事件仍然共同影响结果。

## 6. 岸线事件

事件继续采用“现象先行”。第一次出现时只告诉玩家水发生了什么和三种世界内选择，不展示概率、公式或完整后果表；相似现象累计后，潮池记忆再归纳性格。

第一批事件候选：

| 现象 | 选择方向 | 生命史可能记住什么 |
| --- | --- | --- |
| 退潮晒痕 | 延缓水膜蒸发、让边缘暴露、退回浅水 | 决定稳定附着、完全暴露或随潮播散哪种倾向更占优势 |
| 盐晶爬上湿岩 | 借矿物结面、冲掉盐晶、让耐受谱系试一试 | 岸线偏向矿物附着、清洗回流或耐受突变 |
| 骤雨冲岸 | 固定岸边、顺水播散、先修复浅水循环 | 这片潮池更重视定居、扩散或恢复 |

每个选择至少同时改变一项短期资源/环境结果和一项历史倾向。结果可以让物种进入濒危、退出当前生态并沉淀为遗产，但不能把章节判成失败，也不能删除已经形成的生命史。

## 7. 与既有生命史的连接

### 7.1 源质印记

源质印记继续影响事件池、物种倾向和长期路线，而不是直接指定栖位。例如：

- 偏向潮汐记忆的印记更容易看到水线往返和冲岸事件。
- 偏向晶面或矿物的印记更容易看到湿岩附着与盐晶现象。
- 偏向共生的印记更容易让岸边碎屑和浅水生产重新接上。
- 偏向突变的印记更容易出现大胆的边缘尝试，也更容易承受失衡。

这些影响只调整结构化规则的权重，表达文本仍由本地生成器根据已确定事实生成。AI 不决定概率、成本、惩罚或章节解锁。

### 7.2 图鉴、遗产和潮池记忆

- 图鉴卡在已有生态影响、谱系和脆弱点之外，增加“主要栖位”和“水线关系”的表达。
- 岸线物种的反复观察合并成“附着、暴露、回潮”之类的现象摘要，不逐条罗列 tick 或操作。
- 岸线谱系退出当前生态时，遗产可以成为“空出的岸位”“残留薄水膜”或“耐受警告”，影响以后哪类生命更容易再次尝试。
- 第三章完成记录要同时总结：原有小循环、首次越过水线的谱系、玩家选择的岸线倾向，以及一次失去留下的遗产。

### 7.3 第二章回归

第二章完成存档进入第三章后，生产者、分解者、滤食者和已有生态性格继续有效。旧存档不能因为缺少第三章字段而自动生成岸线物种；只有当第三章的现象和节点被真正见证后，才写入新的章节记录。

## 8. 首页和移动端体验

### 8.1 首页

首页仍然是活着的潮池场景，主操作仍是把发光养料拖进水里。第三章不增加常驻的地图按钮、资源表或生态网络图。

水线通过场景变化被发现：

- 章节开启时，退潮让湿岩边缘短暂显现。
- 贴岸阶段，浅层薄膜和岸缘附着点有轻微不同的动效。
- 事件发生时，晒痕、盐晶或冲刷水纹直接出现在水线附近。
- 章节完成时，水线两侧出现一次短暂的往返反馈，然后回到平静的主场景。

第三章主线展开态文案：

```text
主线：让生命越过水线
潮池已经接上了第一阵往复。现在看看它能不能把这阵水势带到湿岸。
```

收起态只保留阶段名、短目标和轻量进度，不展示三处栖位的完整状态表。

### 8.2 入口、页面和叙事队列

- 第三章不新增底部主入口，优先复用演化、生态干预、图鉴和生命史。
- 章节开启、岸线事件、岸边谱系发现、互斥倾向和章节完成继续进入统一叙事队列。
- 新的“水线可见”反馈必须在玩家关闭章节开启弹层后出现；玩家亲自打开当前可用入口后，下一条导览才可出现。
- 第三章完成弹层直接引导到“潮池记忆”，由生命史总结水线如何改变了这片生态。

### 8.3 文字基线

| 场景 | 文案 |
| --- | --- |
| 章节开启 | `水线露出来了` |
| 主目标 | `让生命越过水线` |
| 湿岸反馈 | `有一支生命随水流附着在湿岸。` |
| 事件前提示 | `退潮把水线推远了，哪些痕迹会留下？` |
| 章节完成 | `生命已经越过水线` |
| 记忆总结 | `浅水与湿岸已经形成材料往返，第一条稳定水线出现了。` |

### 8.4 交互节奏

第三章的交互重点是让玩家把注意力从潮池中心带到边缘，再看两边发生联系：

1. 章节开启弹层收束后，水线在场景中真实退开一小段，湿岩和岸缘痕迹逐渐显现，主线文案只补一句短提示。
2. 当前水线被观察到后，可以提供一次轻量的“引潮”拖拽：玩家把一缕来自小循环的水光拖向湿岸。它只改变观察时机和环境倾向，不指定物种，也不保证结果；回应由当前栖位、源质印记和历史倾向共同决定。
3. 新谱系先在场景里出现，再进入物种发现弹层。玩家先看到它附着湿岩、缩成紧密薄膜或随回潮移动，随后才看到名称和生态解释。
4. 岸线事件确认后，场景保留几秒变化再恢复放置节奏，让玩家有时间看见选择留下的痕迹；减少动态效果时保留水线位置、静态纹理和颜色层次。
5. 章节完成时，视线从岸缘回到浅水，两个栖位之间出现一次往返反馈，随后把这段变化交给潮池记忆，而不是再弹出一张总结数据表。

## 9. 技术落点

第三章实现时继续使用 React + Phaser + Fastify + PostgreSQL，且不改变第一章和第二章的服务端权威存档路线。

### 9.1 共享规则建议

第一版建议扩展现有结构，而不是创建另一套章节系统：

- `LifeHistoryChapter` 增加 `shoreline_differentiation`。
- 增加 `ChapterThreeStage`，阶段对应本文件的六个阶段。
- `ChapterWitness` 增加 `shorelineDifferentiation`，记录水线、栖位、岸线事件、跨栖位往返和完成见证。
- 物种结构增加明确的栖位字段或等价的受约束标签；`niche` 现有文本字段继续用于玩家侧表达。
- `ChapterProgress` 继续作为派生状态，旧字段保留兼容，第三章字段缺失时由 `normalizeGameState` 补默认值。
- 不新增资源类型。岸线压力优先由既有 `tide`、`heat`、`stability`、`volatility`、历史标签和物种状态推导。

### 9.2 节点、事件和 API

以下 ID 是实现前的内容草案，不锁定数值：

- 演化节点：`waterline_exposure`、`shore_attachment`、`niche_split`、`shoreline_exchange`、`shoreline_memory`。
- 互斥分支组：`shoreline_strategy`，包含 `moisture_retention`、`rock_attachment`、`tidal_dispersal`。
- 事件：`ebb_dryness`、`salt_crystal_rise`、`rain_runoff`。
- 历史标签：`waterline_exposed`、`shore_colonized`、`niche_split`、`dry_wet_pressure`、`shoreline_exchange`、`shoreline_memory`。

初版优先复用现有环境操作、演化解锁、生态事件和回响 API。只有现有接口无法表达“观察岸线并留下选择”时，才新增最小 API；不为第三章创建独立存储表或独立货币。

所有成本、概率、惩罚和物种生成规则由 `packages/game-core` 的纯函数定义，服务端校验并写回完整 `GameState`。这些数值需要手工平衡和测试夹具，不交给 AI 或文本生成器。

### 9.3 验证切片

非生产环境的 `POST /debug/third-chapter-save` 与 `smoke:chapter3` 已覆盖 `exposed / shore / niches / event / exchange` 切片，其中 `niches` 明确验证湿岩之外的湿润岸缘姿态；后续逐步覆盖：

- 章节开启但尚未露出水线。
- 水线出现并有一处岸线痕迹。
- 两处栖位形成但尚未恢复材料往返。
- 岸线事件待选择。
- 选择写入历史并形成跨栖位往返。
- 章节完成、生命史摘要存在、旧第二章存档字段保持不变。

第二章的 `smoke:chapter2` 必须继续独立通过，不把第三章状态塞进第二章验收切片。

## 10. 明确不做

- 不做多地图、大世界、自由移动或完整地理模拟。
- 不做新的岸线资源、人口、科技树或自动化管理面板。
- 不做直接选择物种、直接召唤上岸或保证结果的按钮。
- 不做正式文明、意识、账号、分享、多设备同步或复杂统计。
- 不把干湿、盐分和潮汐拆成玩家必须逐项管理的参数表。
- 不把第三章做成第二章角色和事件的复制版；新变化必须来自“栖位”和水线往返。
- 不在设计未确认前生成新的视觉资产。需要新资产时，先确认水线、湿岩和岸缘的视觉方向，再单独提出生成方案。

## 11. 验收标准

- 新玩家在进入第三章后 3 秒内能说出：`我要让生命越过水线。`
- 玩家不看后台数值，也能从场景、主线和事件理解浅水与湿岸正在发生联系。
- 至少两个相连栖位形成稳定痕迹，且跨栖位往返会改变后续生态反馈。
- 岸线选择是三选一的世界内取舍，三项前置条件一致，结果会进入生命史。
- 源质印记、物种角色、已有生态循环和遗产会影响第三章，但没有任何单一因素决定结果。
- 失去岸线谱系时，玩家能看到遗产或空缺被留下，而不是只看到失败提示。
- 第三章完成总结能在“潮池记忆”中说清楚这片潮池怎样从一个中心走向一条岸线。
- 移动端不出现页面级横向滚动，不新增常驻仪表盘；第一章和第二章回归测试继续通过。
