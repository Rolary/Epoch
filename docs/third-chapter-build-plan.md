# 《生态纪元》第三章开发规划

> 版本：体验切片开发阶段。阶段 0/1/2 已完成首轮落地，阶段 3/4 已接入代码视觉、主目标、叙事队列和潮池记忆，正式生图资产等待用户审批。

## 1. 计划目标

把第二章已经形成的第一阵生态往复，做成一次玩家能够看见、触碰、选择并回看的“水线体验”：

```text
第二章完成
-> 水线退开
-> 湿岩和岸痕显现
-> 玩家引导一缕水势到湿岸
-> 退潮事件改变眼前场景
-> 回潮把岸边材料带回浅水
-> 潮池记忆收下这段岸线历史
```

本计划优先验证体验是否成立，再扩展完整章节。每个阶段都有停止条件；未通过当前阶段，不进入下一阶段。

## 2. 不可改变的边界

- 第一章和第二章是稳定回归基线，不为第三章重写或顺手扩张。
- 第三章仍发生在同一片潮池，不做多地图大世界。
- 默认栖位为浅水、潮间湿岩、湿润岸缘；完成第三章不要求三处全部收集。
- 不新增岸线货币、人口、科技表或完整环境参数面板。
- 玩家引导环境和选择倾向，不能直接指定物种或保证某条谱系上岸。
- 规则、成本、概率、惩罚和解锁条件由 `packages/game-core` 决定，生成器只能包装已经确定的生态事实。
- 新视觉资产必须等体验切片通过、插槽尺寸明确，并获得用户明确批准后再制作。
- 第二章 `smoke:chapter2` 必须独立通过，不能依赖第三章字段或阶段。

## 3. 体验目标

第三章必须让玩家感到以下五件事，而不是只看到新的节点名称：

1. 水线在同一场景中进退，场景本身在呼吸。
2. 同一个生态角色在水下和岸边表现出不同姿态。
3. 玩家选择会在眼前留下薄水膜、盐晶、冲刷沟或附着斑。
4. 新谱系先在场景里出现，再通过弹层被记录和命名。
5. 潮池记忆能用短视觉片段回看水线如何形成。

章节主线固定为：

```text
让第一阵往复越过水线，在相连的栖位上留下可以延续的生命。
```

## 4. 第一条垂直切片

完整章节开始前，只做一条可玩、可观察、可回看的短流程：

| 顺序 | 玩家看到或做什么 | 必须验证的体验 |
| --- | --- | --- |
| 1 | 从第二章完成存档进入潮池 | 旧生态循环和原有首页没有被破坏 |
| 2 | 章节开启反馈收束，水线退开一小段 | 第三章不是换页，而是同一场景发生变化 |
| 3 | 湿岩、湿润沉积物和一处附着痕迹显现 | 玩家不看文字也能理解“岸边出现了” |
| 4 | 玩家把一缕水光从浅水拖向湿岸 | 玩家引导的是环境，不是直接命令物种 |
| 5 | 触发一次“退潮晒痕”事件 | 事件取舍和场景变化相连 |
| 6 | 三个选项显示轻量场景预示，确认后水线和岸痕改变 | 选择先改变世界，再写入规则结果 |
| 7 | 一支已有角色在岸边短暂出现或留下痕迹 | 新生命先被看见，随后才被记录 |
| 8 | 回潮把岸边碎屑带回浅水 | 跨栖位关系成立，而不是两个独立装饰区 |
| 9 | 潮池记忆出现三段短片段 | 玩家能回看这次经历，而不是读一条日志 |

这条切片不需要完整三章数值，也不需要全部事件。它只负责回答：第三章是否拥有区别于第二章的体验记忆点。

## 5. 分阶段执行计划

### 阶段 0：体验冻结

**目标**：把第三章的体验支柱变成开发可判断的状态序列。

**任务**：

- 锁定水线的四个视觉状态：隐藏、退潮显现、岸痕残留、回潮往返。
- 锁定“引潮”是否作为第一条切片的轻交互；如果交互负担过高，保留为观察触发，不新增常驻按钮。
- 锁定一个岸线事件：第一版使用“退潮晒痕”。
- 写出事件三个选项的世界内文案、场景预示和确认后反馈。
- 写出潮池记忆三段短片段，不出现后台参数。

**交付物**：一份状态序列表、一份事件文案表、一份移动端验收表。

**停止条件**：如果无法用 20 秒说明“玩家看到了什么、做了什么、留下了什么”，不能进入 coding。

#### 水线状态序列（已冻结）

| 状态 | 进入条件 | 玩家先看到什么 | 持久化事实 |
| --- | --- | --- | --- |
| 隐藏 | 第二章完成，第三章尚未显式启动 | 原有小循环保持稳定，岸边不出现新物种或新痕迹 | 第三章见证全部为默认值 |
| 退潮显现 | 第三章开启并见证第一次退潮 | 水面退开一小段，湿岩和湿润沉积物先于说明文字显现 | `waterline_exposed` |
| 岸痕残留 | 已有角色完成第一次贴岸或岸线事件选择 | 水线附近保留薄水膜、结面、冲刷沟或附着斑 | `shore_colonized` 或对应事件标签 |
| 回潮往返 | 岸边与浅水完成第一次材料交换 | 水纹把岸边碎屑带回浅水，岸痕保留为较弱的静态记录 | `shoreline_exchange` |

#### “退潮晒痕”文案与预示（已冻结）

事件前提示：`退潮把水线推远了，哪些痕迹会留下？`

| 选择 | 世界内说明 | 确认前场景预示 | 确认后反馈 | 长期倾向 |
| --- | --- | --- | --- | --- |
| 延缓薄水膜蒸发 | 让浅水多停留一阵，降低岸边生命最先承受的失水压力。 | 岸缘颜色加深，一层薄水膜覆盖湿岩。 | 水线退得更慢，第一处附着斑得以存活，但暂未向更远岩面扩张。 | 水膜保持 / `moisture_retention` |
| 让湿岩见光 | 允许边缘完全暴露，让留下来的结构面对光、盐与干燥。 | 湿岩反光增强，边缘出现浅色结面。 | 一部分薄膜收缩，少量附着斑仍抓在岩面上，岸线承受更高压力。 | 攀住湿岩 / `rock_attachment` |
| 随回潮退回浅水 | 不强留岸边，让这次尝试跟着下一阵水回到原有循环。 | 回流水纹变强，岸边碎屑向浅水聚拢。 | 岸痕变淡，碎屑被带回池中，浅水循环更快恢复。 | 随潮播散 / `tidal_dispersal` |

三项选择共享同一前置条件。第一版数值、物种压力和遗产结果在阶段 2 由 `packages/game-core` 固定，不由表现文案决定。

#### 移动端首切片验收（已冻结）

| 检查项 | 通过标准 |
| --- | --- |
| 视觉中心 | 水线出现后主潮池仍占主要画面，不新增地图面板。 |
| 单手交互 | 一次性引潮可在拇指可达范围完成，失败时不消耗或指定物种。 |
| 三选一弹层 | 选项标题、说明和代价在 360px 宽度内无横向溢出。 |
| 场景反馈 | 关闭弹层后仍能看见本次选择留下的岸痕。 |
| 减少动态效果 | 以水线位置、颜色和静态纹理表达状态，不依赖持续位移或闪烁。 |

### 阶段 1：共享状态和旧存档基础

**目标**：让第三章能安全地进入现有权威存档，而不破坏第一章和第二章。

**任务**：

- 在 `packages/shared` 增加第三章章节标识和阶段类型。
- 增加受约束的栖位标识，以及第三章见证字段。
- 为 `ChapterProgress` 增加第三章派生阶段，保留旧字段兼容。
- 在 `normalizeGameState` 中为旧存档补默认值，不自动生成岸线物种或岸线历史。
- 确认第三章内容 ID：节点、事件、历史标签、互斥分支组。
- 为缺失字段、第二章完成存档、第二章未完成存档增加单元测试。

**不做**：不新增资源类型，不拆 PostgreSQL 表，不改变已有 API 的权威结算方式。

**通过条件**：`typecheck`、核心测试和第二章旧存档归一化测试通过。

### 阶段 2：核心规则垂直切片

**目标**：先让服务端和 `game-core` 能可靠结算第一条水线流程。

**第一批规则**：

- `waterline_exposure`：第二章完成后允许水线显现。
- `shore_attachment`：已有生态角色在岸边留下第一处结构痕迹。
- `ebb_dryness`：退潮晒痕事件，三项同前置条件的世界内取舍。
- `shoreline_exchange`：岸边与浅水产生一次材料或影响往返。
- `shoreline_strategy`：先实现结构，不急着平衡三条完整长期路线。

**任务**：

- 实现章节三派生进度和见证状态。
- 实现“引潮”或等价观察触发的服务端校验。
- 实现事件选择写入资源、环境、历史标签和物种状态。
- 保证事件结果可以导致濒危、退出或遗产，但不会清空章节进度。
- 增加 `buildThirdChapterDebugSave`，至少提供 `exposed`、`shore`、`event`、`exchange` 四个切片。

**通过条件**：同一存档重复请求不会重复写入同一见证；三项选择前置条件一致；服务端结果与前端预测不分叉。

### 阶段 3：Phaser 场景体验切片

**目标**：让第一条水线流程在现有首页中真实发生。

**任务**：

- 为场景增加水线隐藏、退潮、岸痕、回潮四种派生表现。
- 复用现有潮池背景、中心主体和生态角色资产；用 Phaser 场景效果验证水线运动、湿岩显现和回流节奏。
- 实现一次性“引潮”拖拽或观察触发，拖拽对象只代表水势，不代表物种。
- 让现有生产者、分解者或滤食者的场景反馈在岸边出现不同姿态。
- 实现 reduced motion 下的静态替代状态。

**不做**：不使用临时图形作为最终交付资产，不在此阶段生成新插画，不做完整三栖位地图。

**通过条件**：移动端和桌面端都能看出水线变化；玩家不打开页面也能从场景判断事件已经留下影响；主潮池仍是视觉中心。

### 阶段 4：React 叙事和记忆回看

**目标**：把场景发生的事变成玩家能理解和回看的生命史。

**任务**：

- 接入第三章主线目标和阶段条。
- 复用统一叙事队列承接章节开启、岸线事件、谱系出现和章节见证。
- 让新谱系先在 Phaser 场景出现，再进入物种发现弹层。
- 在生态事件确认框中加入轻量的场景预示，不展示概率表。
- 在“潮池记忆”中实现三段视觉记忆带：水线露出、第一次贴岸、第一次回流。
- 保持首页不增加常驻地图、栖位表或生态网络面板。

**通过条件**：新玩家只看主线、场景和弹层，就能复述“我要让生命越过水线”；关闭弹层后仍能在场景中找到选择留下的痕迹。

### 阶段 5：体验评审门

**目标**：在制作正式资产和完整章节前，判断第一条切片是否值得继续扩展。

**评审流程**：

- 使用第二章完成调试存档，从首页开始体验，不先阅读设计文档。
- 分别体验三个事件选项，观察场景反馈是否真的不同。
- 刷新页面，确认第三章状态、岸痕和生命史没有丢失或重复。
- 用移动端窄屏检查主线、弹层、按钮和记忆带是否溢出。
- 对以下问题逐项回答“是/否”：
  - 画面是否一眼区别于第二章？
  - 水线是否比文字更早告诉玩家发生了什么？
  - 玩家是否感觉自己引导的是环境而不是操控物种？
  - 三项选择是否留下了不同的情绪和视觉结果？
  - 记忆带是否让玩家愿意回看而不是跳过？

**通过门槛**：五项至少四项为“是”，且没有阻断性移动端布局问题。未通过时回到阶段 0 或阶段 3，不进入资产制作。

### 阶段 6：正式视觉资产

**启动条件**：阶段 5 通过，且已确认每个资产的用途、尺寸、状态和出现时机。

**资产优先级**：

1. 水线/湿岩场景层或覆盖层。
2. 岸痕状态：薄水膜、盐晶、冲刷沟、附着斑。
3. 退潮晒痕事件图和选项状态图。
4. 岸边角色姿态或栖位变化图。
5. 潮池记忆带所需的低饱和场景片段。

**流程**：

- 先根据阶段 3 的真实插槽测量尺寸和裁切范围。
- 再提交视觉方向和资产清单，获得用户明确批准。
- 按项目现有 PNG 交付尺寸和 `original-ui` 原图规则生成或绘制。
- 替换体验切片中的临时表现，检查裁切、叠层、透明度、移动端清晰度和 reduced motion 状态。

**停止条件**：资产只是好看但不能表达水线状态、事件结果或角色姿态时，不进入批量制作。

### 阶段 7：完整章节扩展

**目标**：在已验证的体验支柱上扩展完整第三章，而不是重新发明玩法。

**扩展顺序**：

1. 补齐 `niche_split` 和第二个岸线栖位反馈。
2. 补齐 `salt_crystal_rise`、`rain_runoff` 两个岸线事件。
3. 完成三条等条件互斥的岸线倾向：延缓水膜蒸发、强化湿岩附着、随潮播散。
4. 增加岸线角色与既有源质印记、物种组合、遗产效果的连接。
5. 完成跨栖位循环的产出、压力和失衡平衡。
6. 完成章节总结、图鉴栖位信息和遗产回看。
7. 增加 `smoke:chapter3` 的完整阶段切片。

每扩展一个事件或分支，都必须回答：它改变了哪一处场景、哪一个生态关系、哪一段生命史，而不是只增加了一个按钮或一个资源倍率。

### 阶段 8：发布前验收

**自动检查**：

```text
corepack pnpm run check:encoding
corepack pnpm run typecheck
corepack pnpm run build
corepack pnpm test
corepack pnpm run smoke:chapter2
corepack pnpm run smoke:chapter3
```

**浏览器检查**：

- 第二章完成存档进入第三章，章节开启反馈只出现一次且可回看。
- 水线、岸痕、事件预示、事件结果和回潮反馈在桌面端与移动端都可见。
- 首页没有新增常驻管理面板或页面级横向滚动。
- 物种发现、生命史、图鉴、遗产和生态档案的玩家侧命名保持一致。
- 刷新、离线回归和旧存档归一化不丢失第一章、第二章或第三章历史。
- reduced motion 开启时不依赖闪烁、持续位移或粒子才能理解状态。

## 6. 建议的实际工作顺序

后续每次只推进一个阶段，顺序固定为：

```text
阶段 0 体验冻结
-> 阶段 1 状态基础
-> 阶段 2 核心规则切片
-> 阶段 3 Phaser 体验切片
-> 阶段 4 React 叙事回看
-> 阶段 5 体验评审门
-> 阶段 6 正式资产
-> 阶段 7 完整章节
-> 阶段 8 发布验收
```

首轮启动任务及状态：

1. 已冻结“退潮晒痕”切片的状态、文案和三项选择。
2. 已为第二章完成存档增加第三章 `exposed` 调试切片。
3. 已从 `packages/shared` 和 `packages/game-core` 开始实现最小章节三状态，未生成资产。

当前实现进度：

- `waterline_exposure`、`shore_attachment`、`shoreline_exchange` 已进入共享演化规则。
- 一次性 `guide_shore_tide` 引潮动作只引导环境，由现有谱系自行贴岸；重复请求不会重复生成物种或见证。
- `ebb_dryness` 三项选择共享同一事件前置条件，并写入互斥岸线倾向。
- `POST /debug/third-chapter-save` 已覆盖 `exposed / shore / event / exchange`，并提供非持久化浏览器预览。
- Phaser 已表现水线、岸痕预示和回流；React 已接入第三章主目标、叙事队列和三段潮池记忆。
- 正式资产清单见 `docs/third-chapter-ui-asset-backlog.md`，全部处于待审批状态。

## 7. 完成定义

第三章只有同时满足以下条件，才算完成：

- 玩家能用一句话复述当前目标：`让生命越过水线`。
- 场景变化比系统名更早表达水线、岸痕和回潮。
- 至少两个相连栖位形成真实的生态往返。
- 事件选择有不同的场景结果和生命史结果。
- 物种、源质印记、生态组合和遗产都会影响岸线，但玩家不能直接指定结果。
- 潮池记忆能回看水线如何形成，而不是增加原始日志。
- 第一章和第二章的回归、存档、移动端和 reduced motion 验收全部通过。
